# 设计思路

## 1. 产品定位

小文喵是本地桌面文件工具箱，不是内容平台、云服务或营销页。核心目标是让用户高效、安全地处理本机文件和轻量媒体任务。

设计关键词：

- 完整：常见流程有入口、预览、执行、反馈和结果复查。
- 严谨：高风险文件操作必须确认、校验、可撤销或可取消。
- 简要：界面只放必要信息，避免长说明和装饰性内容。
- 稳定：默认策略保守，不为了速度牺牲结果正确性。
- 顺手：高频操作近、按钮短、布局稳定、不跳动、不换行。

## 2. 目标用户

- 需要整理大量本地文件的个人用户。
- 经常处理短视频素材的内容创作者。
- 希望有轻量桌面工具替代脚本或重型软件的技术用户。

这些用户更在意结果可靠、操作路径短、异常可理解，而不是复杂的视觉表现。

## 3. 信息架构

当前模块按工作对象分组：

```text
文件
  ├─ 文件统计
  ├─ 文件归类
  ├─ 批量重命名
  └─ 文件去重

视频
  ├─ 视频截取
  ├─ 批量去头
  └─ 格式转换

图像
  └─ 水印处理
```

左侧栏承载模块切换和全局工具。顶部栏承载当前模块标题、当前模块重置和日志入口。模块内部只放本模块的输入、参数、预览、执行和结果。

## 4. 布局原则

- 桌面优先，兼容窄窗口。
- 左侧导航宽度保持克制，避免空。
- 窄窗口自动折叠为图标栏，模块名不硬挤。
- 页面主体使用白底、浅灰分区、细边框和 8px 以下圆角。
- 不使用大面积装饰图、渐变球、过度插画或营销式 hero。
- 固定格式控件要有稳定尺寸，避免 hover、加载、长文字导致布局跳动。
- 按钮文案尽量 2 到 5 个字；必须长文案时用 tooltip 或说明区承载。

## 5. 重置设计

重置分两层：

- 左侧底部「重置全部」：清空所有模块的路径、结果、预览和临时设置。
- 顶部「重置当前」：只清空当前模块。

运行中任务保护：

- 任意任务运行时禁用「重置全部」。
- 当前模块任务运行时禁用「重置当前」。

模块内部不再重复提供“重置当前模块”这类全局语义按钮。模块内如果有重置，只针对本模块内部的局部参数，例如视频截取的「恢复整段」。

## 6. 文件操作设计

文件写入类功能的体验顺序：

```text
选择输入
  -> 生成预览
  -> 标出冲突和风险
  -> 用户确认
  -> 执行
  -> 展示结果
  -> 必要时提供撤销或复查
```

默认规则：

- 不覆盖已有文件。
- 删除进入回收站。
- 批量任务可取消。
- 结果必须能区分成功、跳过、失败。
- 错误文案直接说明用户下一步可以做什么。

## 7. 视频截取设计

视频截取以“结果接近预览”为默认目标，所以默认开启精确导出。

导出方式：

- 精确导出：重编码，首尾更贴近预览，作为默认。
- 快速导出：无损复制，速度更快，但受关键帧限制，只适合起点接近关键帧的片段。

交互结构：

- 顶部摘要显示总时长、当前片段和画面规格。
- 预览区负责播放、时间轴、缩略帧和帧级操作。
- 右侧设置区只放时间范围、导出方式、进度和主按钮。
- 高级微调默认收起，避免普通用户一上来看到过多控制。

稳定性要求：

- 快速导出后必须校验结果时长，偏差过大时删除输出并提示改用精确模式。
- 处理中锁定编辑，避免参数和输出不一致。
- 取消操作要终止 FFmpeg 进程。

## 8. 日志和反馈

反馈层级：

- Toast：轻量成功、失败和用户操作错误。
- 页面内状态：扫描、预览、结果列表和空状态。
- 任务中心：长任务阶段、进度和取消。
- 日志查看：排查扫描、哈希、FFmpeg 和批量处理问题。

日志不是用户数据仓库，只记录必要运行状态和错误原因。

## 9. 不做什么

当前阶段明确不做：

- 文生图和外部 AI 图片服务。
- 云同步、账号系统、远程文件处理。
- 复杂插件市场。
- 发布前自动下载 FFmpeg、签名或上传安装包。
- 为视觉丰富度增加无关卡片、插图、装饰背景或过长说明。

后续迭代应优先补稳定性、性能、错误恢复和真实样本验证，再考虑新增模块。
