# 开发指南

## 1. 快速启动

```bash
pnpm install
pnpm dev
```

`pnpm dev` 实际执行 `node scripts/tauri.mjs dev`，会启动：

- Vite：`http://localhost:1420/`
- Tauri dev command：`cargo run --no-default-features`

脚本会把 Cargo target 放到 `/private/tmp/file-toolkit-cargo-target/<仓库哈希>`，避免仓库移动后复用旧 `src-tauri/target`。

只看前端样式时可以单独运行：

```bash
pnpm exec vite dev --port 1420
```

## 2. 环境要求

| 依赖 | 要求 |
| --- | --- |
| Node.js | `>=20.19.0 || >=22.12.0` |
| pnpm | `10.28.1` |
| Rust | stable |
| macOS | 需要 Xcode Command Line Tools |
| Windows | 需要 MSVC Build Tools 和 WebView2 |
| Linux | 需要 Tauri WebKit 相关系统依赖 |

开发期 FFmpeg/FFprobe 可从系统 PATH 读取；打包期按平台命名放入 `src-tauri/binaries/`。不要在没有明确确认时下载或替换二进制。

## 3. 常用命令

```bash
pnpm dev
pnpm exec tsc --noEmit
pnpm test
pnpm run build
cargo check --manifest-path src-tauri/Cargo.toml --target-dir /private/tmp/file-toolkit-cargo-target
env CARGO_TARGET_DIR=/private/tmp/file-toolkit-cargo-target pnpm run verify
```

完整验证脚本位于 `scripts/verify.sh`，包含 TypeScript、Vitest、Vite build、Rust fmt、Rust test 和 clippy。

## 4. 新增或修改模块

保持三层结构：

1. Rust command：`src-tauri/src/commands/<module>.rs`
2. TypeScript API：`src/api/<module>.ts`，再从 `src/api/tauri.ts` 导出
3. 页面和工具函数：`src/pages/<Feature>.tsx`、`src/pages/<feature>/utils.ts`

如果新增 command：

1. 在 `src-tauri/src/commands/mod.rs` 导出模块。
2. 在 `src-tauri/src/lib.rs` 引入并注册到 `tauri::generate_handler!`。
3. 在 `src/api/<module>.ts` 包一层类型化函数。
4. 页面只调用 API 封装，不直接散落 command 字符串。
5. 给纯逻辑补 `*.test.ts`。
6. 更新 README 和架构文档。

## 5. UI 开发约定

- 桌面工具优先信息密度和稳定性，不做营销式落地页。
- 页面标题、侧边栏和顶部操作由 `App.tsx` 统一管理。
- 左侧栏宽屏显示分组和文字，窄屏收为图标。
- 模块内操作尽量使用现有 `components/ui/*` 基础组件。
- 按钮文案必须短，避免在 720px 宽度下换行。
- 文件写入、删除、批量处理类操作必须有预览、确认或可撤销策略。
- 模块内「重置」只重置当前模块；左侧「重置全部」由 AppShell 管理。

## 6. 文件操作约定

文件操作是高风险区域，必须遵守：

- 不覆盖已有文件。
- 输入必须是绝对路径普通文件；拒绝符号链接，避免把操作落到链接目标。
- 前端预览只是体验层，Rust 后端仍要校验路径、存在性和冲突。
- macOS/Windows 按大小写不敏感语义判断冲突；悬空符号链接也视为已占用目标。
- 归类和重命名只允许同卷原子移动。遇到跨卷时返回失败并保留源文件，不回退为复制后删除，以免丢失 ACL、扩展属性、resource fork 或 ADS。
- FFmpeg 输出先写入目标目录下权限收紧的私有临时目录，完成后再以无覆盖移动提交；失败和取消会清理临时结果。
- 删除进入回收站，除非后续明确增加“彻底删除”高级选项。
- 去重删除不信任前端开关：每个待删文件与至少一个未选保留副本在删除前都要重新完整哈希，并在最终移动到回收站前再次比对；文件身份或内容变化即跳过。
- 批量操作要保存每项结果，失败项不能吞掉。
- 长任务要上报任务中心，并提供取消入口。
- 取消必须按 task id 匹配，FFmpeg 和 FFprobe 共用任务进程槽；旧取消请求不得影响新任务。
- 取消后不得继续处理后续项。
- 批量取消返回已经完成/失败的部分结果，并明确显示未处理数量，不能伪装成 100% 完成。
- 日志只记录数量、阶段、模式和匿名序号，不写文件名或路径；保留 7 天且单文件最多 5MB。

## 7. 视频处理约定

### 单视频截取

默认使用精确导出：

- 前端偏好 key：`video-cut-precise-mode-v2`
- 精确模式调用 `cut_video_precise`
- 快速模式调用 `cut_video`

快速模式是高级优化，不是默认路径。它使用流复制，受关键帧限制。后端会在快速导出后读取输出时长，如果与目标时长偏差过大，会删除输出文件并提示用户开启精确模式。

用样本复测时可参考：

```bash
ffprobe -hide_banner -v error \
  -show_entries format=duration,start_time:stream=index,codec_type,start_time,duration,nb_frames \
  -of json /path/to/output.mp4
```

### 批量视频任务

- 输出路径必须避让已有文件。
- 使用 task id 区分任务状态。
- 取消时终止当前 FFmpeg 进程并停止后续项。
- 结果要区分 `success`、`skipped`、`failed`。

## 8. 测试策略

优先覆盖纯逻辑：

- 路径生成、冲突预检、重命名规则。
- 时间格式化、帧数计算、视频截取状态派生。
- 水印参数、批量结果统计。

当前已有测试集中在：

- `src/pages/fileOrganize/utils.test.ts`
- `src/pages/batchRename/utils.test.ts`
- `src/pages/videoCut/utils.test.ts`
- `src/pages/watermark/utils.test.ts`

涉及 Rust command 的改动至少跑：

```bash
cargo check --manifest-path src-tauri/Cargo.toml --target-dir /private/tmp/file-toolkit-cargo-target
```

提交前尽量跑完整：

```bash
env CARGO_TARGET_DIR=/private/tmp/file-toolkit-cargo-target pnpm run verify
```

## 9. 发布和生成物边界

不要提交：

- `node_modules/`
- `dist/`
- `tmp/`
- `src-tauri/target/`
- `src-tauri/binaries/`
- 安装包
- 本地视频、图片、用户文件样本
- 私有日志或生产数据

本地版本准备使用：

```bash
./tag.sh v0.1.0
```

脚本只更新三处版本、同步 Cargo.lock、运行完整验证并展示 diff；不会 commit/tag/push。`.github/workflows/release.yml` 仅允许手动触发，只生成 unsigned prerelease draft，并要求每个平台 FFmpeg archive 的 HTTPS URL、SHA-256 与再分发确认。

没有明确确认时不要执行：

- `tag.sh`
- `git push`
- GitHub release
- 签名、notarization、上传安装包
- 下载或替换 FFmpeg 二进制

公开发布还必须先补齐应用许可证、第三方许可/NOTICE、FFmpeg 来源清单、平台签名/notarization、实机安装验收、发布 owner 和回滚方案。draft 不代表可分发。
