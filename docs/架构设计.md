# 架构设计

## 1. 总体架构

小文喵是本地桌面工具，不启动业务 HTTP 服务。前端运行在 Tauri WebView 中，通过 Tauri IPC 调用 Rust command。耗时任务由 Rust 执行文件系统、哈希、FFmpeg 或图像处理，前端通过事件接收进度并维护任务状态。

```text
React WebView
  ├─ AppShell：导航、模块挂载、重置、日志入口
  ├─ pages/*：功能页面
  ├─ components/TaskCenter：全局任务状态
  └─ api/*：TypeScript command 封装
        │ invoke/listen
        ▼
Tauri Runtime
        │ command/event
        ▼
Rust commands
  ├─ file_stats：文件统计
  ├─ organize / rename：文件移动与重命名
  ├─ dedup：去重扫描、缩略图、删除到回收站
  ├─ video / convert：视频截取、批量去头、格式转换
  ├─ watermark：水印处理
  ├─ system：路径存在、打开、显示、元信息
  └─ logger：本地日志
        │
        ▼
本机文件系统 / FFmpeg / FFprobe / 系统打开能力
```

### 2.1 AppShell

`App.tsx` 负责桌面应用外壳：

- 左侧导航按「文件 / 视频 / 图像」分组。
- 宽度小于 `920px` 时自动折叠为图标栏。
- `PageSlot` 只在模块首次访问后挂载，避免一次性加载所有页面。
- 左侧「重置全部」递增所有模块 `key`，顶部「重置当前」只递增当前模块 `key`。
- 通过 `TaskCenter` 判断重置是否应禁用，避免运行中任务被卸载。

### 2.2 页面模块

页面保持“一个模块一个页面”的边界：

- 页面组件负责交互状态、表单、预览和用户确认。
- 纯计算逻辑放在 `src/pages/<feature>/utils.ts`，并配套 `*.test.ts`。
- Tauri 调用必须走 `src/api/*` 封装，不在页面里散落 command 名称。

### 2.3 任务中心

`TaskCenter` 提供全局任务状态：

- 页面用 `useTaskStatus(taskId, state)` 上报任务阶段、进度和取消入口。
- `TaskStatusBar` 展示当前运行任务。
- AppShell 用 task id 判断「重置全部 / 重置当前」是否可用。

## 4. 核心数据流

### 4.1 文件扫描

```text
选择目录
  -> 前端 invoke(scan_directory)
  -> Rust walkdir 遍历
  -> 周期性 emit(file-stats-progress)
  -> 返回统计结果
  -> 前端渲染表格和摘要
```

扫描只读，不修改用户文件。

### 4.2 文件归类和批量重命名

```text
选择文件/目录
  -> 前端生成预览
  -> 前端检查目标冲突
  -> 用户确认执行
  -> Rust 再次校验目标路径
  -> 执行移动或重命名
  -> 返回成功/失败结果
  -> 前端保留最近一次成功项用于撤销
```

这两类功能都必须遵守“不覆盖已有文件”。后端不能只信任前端预检。`file_ops` 统一处理绝对路径、普通文件/符号链接判断、平台冲突键和无覆盖移动；跨卷不会复制后删除。纯大小写重命名通过同目录私有中间名完成，失败时优先恢复原路径。

### 4.3 文件去重

```text
选择目录
  -> Rust 按文件大小分组
  -> 对可疑组计算轻量尾部/中段指纹，缩小候选范围
  -> 对候选重复组计算完整 xxHash3，确认内容一致
  -> 返回重复组
  -> 前端分组展示与选择
  -> 用户确认删除
  -> Rust 流式打开待删文件和一个保留副本
  -> 删除前重新完整哈希并复查文件身份
  -> 内容一致且均未变化时删除到回收站
```

删除动作必须有二次确认，并保证每组至少一个未选保留副本。后端按候选流式打开文件，避免大重复组耗尽文件描述符；最终仍以路径调用系统回收站 API，因此无法消除外部进程在最后一次复查与系统调用之间的所有竞态，发现任何可见变化时默认拒绝删除。日志只记录数量和匿名失败项，不记录路径。

### 4.4 视频截取

单视频截取有两种导出方式：

- 精确导出：默认开启，使用重编码，起止点更贴近预览。
- 快速导出：使用流复制，速度快但受关键帧限制，只适合起点接近关键帧的场景。

```text
选择视频
  -> get_video_info / generate_timeline_frames
  -> 前端时间轴预览和帧级微调
  -> 用户选择输出路径
  -> precise=true 调用 cut_video_precise
  -> precise=false 调用 cut_video
  -> Rust 执行 FFmpeg
  -> 精确模式 emit(video-progress)
  -> 快速模式完成后校验输出时长
```

快速模式会在导出后读取输出时长。如果与目标时长偏差过大，会删除错误输出并返回明确错误，避免留下不可用文件。

### 4.5 批量去头、格式转换和水印处理

批量任务共享原则：

- 前端先收集输入并显示待处理列表。
- Rust 逐项处理，周期性推送进度。
- 支持取消，取消后不得继续写后续文件。
- 输出路径必须避让已有文件。
- 结果页显示成功、跳过和失败项，便于复查。
- task id 同时绑定进度、取消标志和当前 FFmpeg/FFprobe 进程，延迟到达的旧取消不会终止新任务。
- 输出先写同目录私有临时目录，再无覆盖提交；取消只保留已经提交的部分结果。

## 5. FFmpeg 路径策略

`commands/ffmpeg_utils.rs` 负责解析 FFmpeg/FFprobe：

1. 优先找应用打包资源。
2. 开发环境可回退系统 PATH。
3. 打包时二进制放入 `src-tauri/binaries/`，命名按平台 target 区分。

Agent 不自动下载、替换或发布 FFmpeg 二进制。二进制来源、许可证和再分发边界必须发布前人工确认。

Release workflow 仅支持手动 draft：每个 target 使用独立 archive URL 和 SHA-256，校验根目录文件名并执行 `ffmpeg/ffprobe -version` 后才构建。draft 标记 unsigned/prerelease，不自动公开。

## 6. 安全和稳定性边界

- 默认本地处理，不上传用户文件。
- 文件写入类功能不覆盖已有文件。
- Tauri asset protocol 静态 scope 只保留 `$TEMP/**`；用户选择的图片按单文件动态授权，避免默认暴露 HOME 或卷目录。
- 删除默认进入回收站。
- 长任务必须有运行状态和取消入口。
- 运行任务期间禁止重置对应模块，避免中断状态丢失。
- 日志用于排障，不写 token、cookie、完整连接串、私密 openid、生产导出数据、文件名或路径；日志按 7 天/5MB 收敛，查看器只读最近 256KB/1000 行。
- `node_modules/`、`dist/`、`tmp/`、`src-tauri/target/`、`src-tauri/binaries/` 和本地媒体样本不进入 Git。

## 7. 性能策略

| 场景 | 策略 |
| --- | --- |
| 大目录扫描 | walkdir 流式遍历，定期进度上报，支持取消 |
| 去重 | 先按大小过滤，再对可疑组做哈希 |
| 大文件哈希 | 流式读取，避免一次性载入内存 |
| 视频预览 | 优先 HTML video；不适合直接预览时生成静态帧 |
| 视频截取 | 默认精确，保证结果；快速模式只作为关键帧友好场景的优化 |
| 批量任务 | 逐项执行，保存每项结果，支持取消 |
