# 技术选型

## 1. 当前技术栈

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | WebView 外壳、IPC、打包能力 |
| 前端 | React 19 + TypeScript | 页面和交互 |
| 样式 | Tailwind CSS 4 + CSS 变量 | 清爽桌面工具 UI |
| 构建 | Vite 7 | 前端开发和构建 |
| 后端 | Rust | 文件系统、哈希、进程、图像和视频处理 |
| 测试 | Vitest + Cargo test/check/clippy | 前端纯逻辑和 Rust 检查 |
| 媒体处理 | FFmpeg / FFprobe | 视频截取、格式转换、缩略图和部分图像处理 |

## 2. 为什么选 Tauri

文件工具箱的核心压力在本机文件系统、批量处理、哈希、FFmpeg 进程和跨平台打包。Tauri 的优势：

- Rust 后端适合 CPU/IO 密集型任务。
- 包体积和内存占用比 Electron 更低。
- 默认权限更收敛，适合本地文件处理。
- 前端仍能使用 React 生态完成复杂交互。

代价：

- Rust 和 Tauri 插件约束增加开发复杂度。
- WebView 跨平台表现仍需实测。
- 发布链路要处理签名、notarization、FFmpeg 再分发等问题。

## 3. 前端选型

### React + TypeScript

选择理由：

- 组件化适合多个独立工具模块。
- 类型能约束 Tauri command 返回数据。
- 现有代码已采用 React hooks 和少量 context。

当前状态管理策略：

- 页面内部使用 `useState` / `useMemo` / `useEffect`。
- 全局长任务使用 `TaskCenter` context。
- 暂不引入 Redux 或 Zustand，避免过度设计。

### Tailwind CSS + 本地 UI 组件

当前 UI 基础组件在 `src/components/ui/`。设计目标是 Ant Design 式的清爽桌面工具感：浅背景、白面板、细边框、蓝色主操作、低阴影和稳定尺寸。

不使用完整 antd 依赖，原因：

- 当前组件数量可控。
- Tauri 桌面端需要更强的布局和尺寸控制。
- 避免引入大体积组件库后再覆盖样式。

## 4. Rust 后端选型

主要 crate：

| Crate | 用途 |
| --- | --- |
| `walkdir` | 目录递归扫描 |
| `xxhash-rust` | xxHash3 快速哈希 |
| `rayon` | 并行处理 |
| `tokio` | 异步任务 |
| `serde` | IPC 数据序列化 |
| `trash` | 删除到回收站 |
| `image` / 自定义模块 | 水印处理和图像元信息 |

后端职责：

- 只读扫描、路径元信息、打开/显示文件位置。
- 文件移动、重命名、删除等写入操作。
- 去重哈希和缩略图生成。
- FFmpeg/FFprobe 进程调度、进度解析和取消。
- 本地日志写入和查询。

## 5. FFmpeg 策略

当前选择：开发期可使用系统 PATH，打包期使用内置二进制。

原因：

- 视频截取、批量去头、格式转换都依赖 FFmpeg。
- FFprobe 用于读取时长、帧率、尺寸和输出校验。
- 用户侧开箱即用比要求安装 FFmpeg 更符合桌面工具定位。

风险：

- 二进制包体积增加。
- 不同平台二进制来源、许可证和再分发边界需要发布前确认。
- macOS/Windows 发布还涉及签名和安全提示。

工程约束：

- `src-tauri/binaries/` 不进入 Git。
- Agent 不自动下载、替换或发布 FFmpeg 二进制。
- 快速视频截取受关键帧限制，不能作为默认精确方案。

## 6. 文件处理策略

| 场景 | 技术策略 |
| --- | --- |
| 文件统计 | Rust 递归遍历，周期性进度上报 |
| 文件归类 | 前端生成预览，Rust 执行移动并拒绝覆盖 |
| 批量重命名 | 前端生成新名称预览，Rust 执行重命名并拒绝覆盖 |
| 文件去重 | 大小分组后计算 xxHash3，删除到回收站 |
| 日志 | Rust 写本地日志，前端筛选和复制 |

文件写入类功能必须做后端再校验，不能只依赖前端预览。

## 7. 视频处理策略

单视频截取：

- 默认精确导出，使用重编码，结果更接近预览。
- 快速导出使用流复制，只适合关键帧附近起点。
- 快速导出后校验输出时长，异常则删除输出并提示精确模式。

批量视频：

- 逐项处理，记录每项成功/跳过/失败。
- 支持取消并终止当前 FFmpeg 进程。
- 输出路径自动避让已有文件。

格式转换：

- 面向常见 MP4/MOV/GIF 和高/中/低画质。
- 不暴露复杂编码参数，避免增加判断成本。

## 8. 安全边界

- 本地处理，不上传用户文件。
- 不提交样本媒体、运行日志、缓存和打包产物。
- 删除默认进回收站。
- 文件移动/重命名/输出必须避免覆盖。
- 长任务有进度和取消入口。
- 发布前必须人工确认 FFmpeg、签名、notarization、安装包和回滚策略。

## 9. 暂不采用

| 技术/方向 | 原因 |
| --- | --- |
| Electron | 包体积和内存占用不适合轻量工具 |
| Redux | 当前跨页共享状态少，`TaskCenter` 足够 |
| 完整 antd 依赖 | 当前需要定制桌面工具布局，基础组件已够用 |
| 云端 AI 图片生成 | 已移除，产品边界回到本地文件处理 |
| 插件市场 | 当前阶段过度设计，先稳定核心模块 |
